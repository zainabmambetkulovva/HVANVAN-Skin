# 1. ОБЩАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ

## 1.1. Описание проекта

HVAVAN Skin — полноценная коммерческая цифровая платформа для продажи косметической продукции и централизованного управления магазинами.

Проект включает четыре основные части:

1. **Веб-сайт** — интернет-магазин для покупателей.
2. **Мобильное приложение** — версия интернет-магазина для iOS и Android.
3. **Административная панель** — централизованное управление всей системой.
4. **Панель менеджера** — выполнение операционных задач в рамках выданных разрешений.

Платформа должна объединять онлайн-продажи, складской учёт, управление филиалами, заказы, платежи, программу лояльности UDS, уведомления и аналитику.

## 1.2. Цель проекта

Создать единую систему, которая позволит:

- Продавать косметическую продукцию через сайт и мобильное приложение.
- Предоставлять клиентам удобный каталог товаров.
- Принимать и обрабатывать онлайн-заказы.
- Организовать доставку и самовывоз.
- Контролировать остатки товаров в каждом филиале.
- Управлять несколькими магазинами из одной системы.
- Интегрировать платёжные сервисы.
- Подключить существующую систему лояльности UDS.
- Автоматизировать уведомления клиентов и сотрудников.
- Получать подробную аналитику продаж и деятельности филиалов.

## 1.3. Основные принципы системы

- Единая база данных для всех платформ.
- Синхронизация товаров, цен, заказов и остатков.
- Раздельный складской учёт по филиалам.
- Управление правами сотрудников.
- Безопасное хранение клиентских данных.
- Автоматизация повторяющихся бизнес-процессов.
- Адаптивный интерфейс для разных устройств.

# 4. РЕГИСТРАЦИЯ И АВТОРИЗАЦИЯ

## 4.1. Регистрация клиента

Основной способ регистрации — номер телефона.

Процесс регистрации:

1. Клиент вводит номер телефона.
2. Система отправляет SMS-код.
3. Клиент вводит полученный код.
4. Система проверяет код.
5. При успешной проверке создаётся аккаунт.
6. Клиент получает доступ к личному кабинету.

Для основной регистрации пароль не требуется.

## 4.2. Способы авторизации

Предусмотренные способы:

- Phone.
- Google.
- Email.
- Apple.
- Password.

Точная логика входа по Email и Password требует дополнительного согласования, поскольку основная регистрация предусмотрена без пароля.

## 4.3. Защита авторизации

Система должна:

- Проверять корректность данных.
- Проверять SMS-код.
- Защищать от частых попыток входа.
- Предусматривать ограничение повторной отправки кода.
- Защищать пользовательские сессии.
- Разделять клиентскую и административную авторизацию.

# 9. КОРЗИНА И ОФОРМЛЕНИЕ ЗАКАЗА

## 9.1. Корзина

Функции:

- Добавление товаров.
- Удаление товаров.
- Изменение количества.
- Пересчёт общей стоимости.
- Применение промокода.
- Отображение итоговой суммы.

Оформление заказа без регистрации запрещено.

Для оформления заказа клиент должен авторизоваться.

## 9.3. Процесс оформления заказа

Последовательность:

1. Клиент открывает корзину.
2. Проверяет список товаров.
3. Выбирает способ получения.
4. При необходимости выбирает филиал самовывоза.
5. Указывает адрес доставки.
6. Выбирает способ оплаты.
7. Применяет промокод при наличии.
8. Подтверждает оформление заказа.
9. Заказ создаётся в системе.
10. Менеджер получает уведомление.
11. Менеджер подтверждает заказ.
12. Клиент получает уведомление о результате.

# 12. СКЛАДСКОЙ УЧЁТ

## 12.1. Общие требования

Складской учёт ведётся отдельно по каждому филиалу.

Система должна хранить:

- Товар.
- Филиал.
- Текущее количество.
- Минимальный остаток.
- Историю складских операций.

## 12.2. Изменение остатков

Администратор и менеджер могут изменять остатки.

Операции:

- Поступление.
- Продажа.
- Списание.
- Корректировка.

Поступление товаров выполняется вручную.

Инвентаризация проводится вручную через административную панель.

## 12.3. Минимальный остаток

Для каждого товара и филиала задаётся индивидуальный минимальный остаток.

При достижении минимального значения система отправляет уведомление администратору и ответственным менеджерам.

## 12.4. Списание товара

После подтверждения заказа менеджером товар списывается со склада соответствующего филиала.

При отмене заказа товар автоматически возвращается на склад, если он ранее был списан.

Система должна предотвращать двойное восстановление остатков.

## 12.5. История операций

Все складские операции должны сохраняться:

- Тип операции.
- Товар.
- Количество.
- Филиал.
- Дата и время.
- Сотрудник, выполнивший операцию.

## 12.6. Резервирование

Отдельное резервирование товара не предусмотрено.

Поведение системы при изменении остатков между созданием и подтверждением заказа необходимо дополнительно согласовать.

# 14. ОПЛАТА И ПЛАТЁЖНЫЕ ИНТЕГРАЦИИ

## 14.1. Способы оплаты

Предусмотрены:

- Cash — наличные.
- Wallet — электронный кошелёк.
- Transfer — банковский перевод.
- QR — оплата по QR-коду.

## 14.2. Планируемые платёжные сервисы

1. MBank.
2. O!Деньги.
3. Элкарт.
4. Balance.
5. Finik.
6. Optima Bank.
7. Bakai Bank.

## 14.3. Способы онлайн-оплаты

Клиенту должны быть доступны два сценария.

### Сценарий 1 — онлайн-оплата

Клиент выбирает платёжный сервис и оплачивает заказ непосредственно через поддерживаемый платёжный механизм.

### Сценарий 2 — QR-оплата

Система предоставляет QR-код для оплаты через выбранный банк или электронный кошелёк.

## 14.4. Электронный чек

После успешной оплаты система должна сформировать электронный чек.

## 14.5. Ошибка оплаты

При неуспешной оплате клиенту предлагается повторить попытку.

Заказ и платёжные статусы должны обрабатываться раздельно, чтобы избежать ошибочного подтверждения оплаты.

## 14.6. Возврат денег

Возврат денежных средств оформляется через менеджера.

Деньги возвращаются тем же способом, которым была произведена оплата, если это поддерживается платёжным провайдером.

Фактическая интеграция каждого платёжного сервиса зависит от доступности API, условий подключения и договоров.

- Получение истории операций.
- Начисление бонусов.
- Списание бонусов.
